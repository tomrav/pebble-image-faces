# Photo Face and Ghibli Time

Two image watchfaces for Pebble Time 2 (`emery`) and Pebble Round 2 (`gabbro`) built on one shared C engine
and phone transport. This file is the instruction set for every coding agent.

## Core constraints

- Target Pebble Time 2 (`emery`) and Pebble Round 2 (`gabbro`) unless the user explicitly asks for something else. Every face change is checked on both.
- Round 2 is a 260x260 circle with the same 128KB of app RAM, too little for a 260x260 8-bit bitmap beside its PNG. Round images are STRIP PACKS (several 260-wide PNGs back to back) that `src/shared/image-face/face-image.h` decodes strip by strip into a 6-bit canvas of the circle's pixels (64 colours, ~39.8KB). Bundled round images are raw `.pack` resources under the same name as the emery PNG, split by `targetPlatforms`. Keep gabbro's resources under the 256KB store limit (the build only warns at 1MB).
- `messageKeys` in each face's package.json are an append-only wire ABI: array order assigns numeric IDs shared by the phone JS and watch binary, which can transiently run different versions. Never insert mid-list; always append. After any messageKeys or version change, run `pebble clean` before building (stale message_keys.auto.h / appinfo otherwise ships) and verify the .pbw version with `unzip -p <pbw> appinfo.json` before uploading a release.
- The C runtime lives in `src/shared/image-face/`. The copies under `src/faces/*/src/c/face-*.h` and `src/pkjs/image-transfer.js` are generated by `npm run pebble:sync-runtime` and must not be hand-edited. The root build scripts sync automatically.
- `src/faces/ghibli-face/` and `docs/faces/ghibli/` are generated by `npm run pebble:gen-faces` from `src/shared/franchise-face/` and `media/epaper/`. Edit the sources, not the output. Photo Face is standalone; its photo library regenerates with `npm run pebble:gen-photo-face` from `docs/photo-face/img/` + `library.json`.
- Per-app persistent storage is 1 MiB on PebbleOS 4.9.171+, 4 KiB before. Records are 256 bytes (`PERSIST_DATA_MAX_LENGTH`), so images are stored as runs of records with a header written last. `persist_get_max_size()` is missing from older firmware: gate it on `watch_info_get_firmware_version()` (>= 4.9.171) or the app faults at launch. Reference: `img_slot_*` in `src/shared/image-face/face-cache.h`.
- Watchfaces get no touch events and no button clicks from PebbleOS. Advance happens on a wrist shake or a timer only.
- Watch-image quantization is `scripts/lib/emery-image.py`; its browser twin for uploads is `docs/shared/pebble-image.js`. Change them together. Both write rect PNGs and round strip packs (`shape: "round"` / `?platform=gabbro`). Both dither against `DISPLAY`, the colours the panel actually shows for the 64 palette entries (measured from the SDK emulators, A/B tested on a Time 2 on 2026-10-14); keep the two tables identical.
- Re-converting hosted (`r:`) images needs `HOSTED_GEN` bumped in both phone scripts (Photo Face `index.js`, `pkjs.tmpl.js`): the watch never rewrites a cached image under the same id, and the site must be published before any build with the new generation runs, or watches cache old bytes under the new ids.
- Ghibli's art is cut from the originals in `media/sources.csv` by `npm run pebble:import-round-art`: `media/epaper-round/` for Round 2, and `media/epaper/` recut in place for Time 2 (except cuts whose original isn't known).
- Never add AI attribution or co-author trailers to commits or PR descriptions.

## Workflow

- Build: `npm run pebble:build -- <photo-face|ghibli-face>`
- Emulator: `npm run pebble:emulator -- <project>`; logs: `npm run pebble:logs -- <project>`
- Smoke test with screenshot: `npm run pebble:test -- <project>`
- Runtime regressions (no SDK needed): `npm run pebble:test-runtime`
- Settings pages + streamed images publish with `npm run pebble:publish-config` (Cloudflare Pages direct upload; the target project is `PAGES_PROJECT`).
- Emulator, logs, screenshot and test take `--platform gabbro` (default emery).
- Only the first watchface install per emulator session reliably launches; `npm run pebble:reset` before retrying. `pebble emu-tap --emulator <emery|gabbro>` injects a shake.
- Every change to a face needs a build, an emulator install and a visual check. Release passes also need store screenshots (200x228, plus 260x260 for Round 2), banner (720x320) and icons (80/144), regenerated by `store-assets/make-assets.py`.

## If you are running on the devbox Mac (added 2026-10-12)

**Scope check first:** this section applies only when the session runs as the `devbox` user
(`id -un` prints `devbox`, checkout at `/Users/devbox/projects/pebble-image-faces`). Anywhere else, ignore it.

- **Toolchain on devbox:** `pebble` (pebble-tool 5.0.40, installed with uv into `~/.local/bin`),
  SDK 4.33.1 under `~/Library/Application Support/Pebble SDK`, Node 24 via nvm. The image scripts
  call plain `python3` and need Pillow + numpy: prepend `~/.local/share/devbox/pebble-py/bin` to
  PATH before `pebble:gen-faces` / `pebble:gen-photo-face`. Homebrew is Tom's and read-only; never
  `brew install`, ask Tom.
- **Emulator only on devbox:** no watch is attached; `pebble:cloud`/device installs need Tom.
  Use `npm run pebble:reset` between emulator sessions as documented above.
- **Browser:** `npx agent-browser` headless, or the shared DEV instance through
  `~/projects/devbox/scripts/dev-browser.sh ab <session> …` (claude-in-chrome deviceId
  `a3ba6c61-b88e-4654-8fd3-37b42242113b`). Never launch another Chrome; Playwright is not used.
- **Publishing:** `.env` (gitignored) holds the shared devbox Cloudflare token, so
  `npm run pebble:publish-config` needs no `wrangler login`; never run `wrangler login` on devbox
  and never print `.env`. The settings pages are live for installed watches: publish only when asked.
- Platform requests (new projects, host changes) go to the devbox project's **Q** thread.
- **Commits:** commit and push only in this repository. Never commit or push to
  `~/projects/devbox` or any other repository, even if a task asks for it; put anything
  for the devbox records (manifest, host change log) in your final report and Q records it.
