# Photo Face and Ghibli Time

Two image watchfaces for Pebble Time 2 (`emery`) built on one shared C engine
and phone transport. This file is the instruction set for every coding agent.

## Core constraints

- Target Pebble Time 2 as `emery` unless the user explicitly asks for something else.
- `messageKeys` in each face's package.json are an append-only wire ABI: array order assigns numeric IDs shared by the phone JS and watch binary, which can transiently run different versions. Never insert mid-list; always append. After any messageKeys or version change, run `pebble clean` before building (stale message_keys.auto.h / appinfo otherwise ships) and verify the .pbw version with `unzip -p <pbw> appinfo.json` before uploading a release.
- The C runtime lives in `src/shared/image-face/`. The copies under `src/faces/*/src/c/face-*.h` and `src/pkjs/image-transfer.js` are generated by `npm run pebble:sync-runtime` and must not be hand-edited. The root build scripts sync automatically.
- `src/faces/ghibli-face/` and `docs/faces/ghibli/` are generated by `npm run pebble:gen-faces` from `src/shared/franchise-face/` and `media/epaper/`. Edit the sources, not the output. Photo Face is standalone; its photo library regenerates with `npm run pebble:gen-photo-face` from `docs/photo-face/img/` + `library.json`.
- Per-app persistent storage is 1 MiB on PebbleOS 4.9.171+, 4 KiB before. Records are 256 bytes (`PERSIST_DATA_MAX_LENGTH`), so images are stored as runs of records with a header written last. `persist_get_max_size()` is missing from older firmware: gate it on `watch_info_get_firmware_version()` (>= 4.9.171) or the app faults at launch. Reference: `img_slot_*` in `src/shared/image-face/face-cache.h`.
- Watchfaces get no touch events and no button clicks from PebbleOS. Advance happens on a wrist shake or a timer only.
- Watch-image quantization is `scripts/lib/emery-image.py`; its browser twin for uploads is `docs/shared/pebble-image.js`. Change them together.
- Never add AI attribution or co-author trailers to commits or PR descriptions.

## Workflow

- Build: `npm run pebble:build -- <photo-face|ghibli-face>`
- Emulator: `npm run pebble:emulator -- <project>`; logs: `npm run pebble:logs -- <project>`
- Smoke test with screenshot: `npm run pebble:test -- <project>`
- Runtime regressions (no SDK needed): `npm run pebble:test-runtime`
- Settings pages + streamed images publish with `npm run pebble:publish-config` (Cloudflare Pages direct upload; the target project is `PAGES_PROJECT`).
- Only the first watchface install per emulator session reliably launches; `npm run pebble:reset` before retrying. `pebble emu-tap --emulator emery` injects a shake.
- Every change to a face needs a build, an emulator install and a visual check. Release passes also need store screenshots (200x228), banner (720x320) and icons (80/144), regenerated by `store-assets/make-assets.py`.
